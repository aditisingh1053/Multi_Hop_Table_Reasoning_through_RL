3 · Dataset & approach

HybridQA as a graph; PPO picks the next entity

Data: HybridQA

Wikipedia tables whose cells link to passages (Chen et al., 2020).

Per question: 15.9 rows + 33.2 passages = 49 entities.

Gold evidence is traced by string match: noisy, unique for only 56% of questions.

5,000 train · 1,000 val (unseen tables) · 3,466 dev = test

Statequestion, selected evidence, last entity (frozen MiniLM + 22 features)

Data: HybridQA, Wikipedia tables whose cells are hyperlinked to passages. For each question we build a graph with one node per row and one per linked passage, about 49 entities per question. Gold evidence exists only as answer locations traced by string matching, which is noisy and unique for only about 56% of questions, so we treat it as a set of acceptable targets. We train on 5,000 questions, select checkpoints on 1,000 questions from different tables, and test on the full official dev set of 3,466 questions. The MDP: the state is the question, the evidence chosen so far and the last entity, embedded once with a frozen MiniLM encoder plus 22 hand-made features. The actions are any row, the five best-matching passages, passages linked from chosen rows, and STOP. The reward is the frozen reader's F1 on the chosen evidence, minus 0.02 per entity, plus an optional evidence-recall term written as potential-based shaping, which provably leaves the optimal policy unchanged. The policy is a pointer network with a separate critic, trained with PPO and GAE, and we compare it with behaviour cloning, REINFORCE and GRPO under identical rewards.
